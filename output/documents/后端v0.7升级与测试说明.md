# 后端 v0.7 升级与测试说明

更新日期：2026-11-09。适用于当前 Python 接收程序，依据用户提供的《接口文档(2).md》v0.7。

## 1. 已完成的修改

| 修改 | 实际行为 |
| --- | --- |
| 后端访问凭证 | entry/exit 都发送 `X-Gate-Token` 请求头，不把凭证放进 URL |
| 停车场 | 两台相机使用用户确认的 `LOT-DEFAULT`，请求中带 `lotId` |
| 响应校验 | 成功时必须匹配车牌和停车场，且 `lift` 必须是布尔值 |
| HTTP 401 | 状态 `auth_failed`，不开闸、不播报 |
| HTTP 429 | 状态 `rate_limited`，记录 `Retry-After`，本事件不自动重试 |
| 调用间隔 | 默认同一后端同一路径在上一请求结束后至少间隔 3 秒，入口和出口独立 |
| 旧记录迁移 | 事务内建立含 lotId 的去重主键，保留旧表副本与全部旧状态 |
| 审计 | 新事件保存当时的后端地址和停车场；历史详情按历史归属查询 |
| 配置测试 | 使用独立固定样本，实际后端 IP 改变不再导致旧断言失败 |

相机上报路径仍是 `/api/camera/events`。开闸 GPIO 和 `0x22` 语音协议没有改变。
计费、充电时长统计和停车单状态仍由业务后端负责；接收端不自行实现收费算法。

## 2. 当前配置

在项目根目录 [config.ini](../../config.ini) 的 `[backend]` 中：

```ini
[backend]
url = https://8.153.17.56
lot_id = LOT-DEFAULT
legacy_lot_id = LOT-DEFAULT
token_env = GATE_API_TOKEN
token_file = backend_token.txt
min_interval_seconds = 3
```

| 配置 | 解释 |
| --- | --- |
| `url` | 接收电脑实际可访问的后端根地址，不加 entry/exit 路径 |
| `lot_id` | 当前两台相机所属停车场，允许 1～32 位字母、数字、下划线、中划线 |
| `legacy_lot_id` | 旧版未发送 lotId 的本地后端记录首次迁移时归属哪个停车场；确认使用 LOT-DEFAULT |
| `token_env` | 凭证环境变量名称，优先读取 |
| `token_file` | 未设置环境变量时使用的本地凭证文件，相对 config.ini 所在目录 |
| `min_interval_seconds` | 本地同接口冷却间隔，默认 3 秒，程序接受有限数值 0～30；只有后端同步修改限流后才调整 |

`legacy_lot_id` 只决定第一次旧表迁移时的映射；以后改这个值不会搬动已经迁移的数据。

### 凭证放在哪里

本机已经根据你提供的接口文档建立 `backend_token.txt`，内容只是一行后端访问凭证。程序不显示凭证本身。
该文件被 `.gitignore` 排除，不会随普通 Git 提交上传。不要把凭证粘贴到源码、README 或已经纳入 Git 的 config.ini。

换电脑或从 GitHub 克隆代码后，需要自行创建同名文件并填入后端当前凭证，或者设置 `GATE_API_TOKEN` 环境变量。
如果环境变量存在，它会覆盖文件；环境变量为空或含非法字符时会报错，不会悄悄改用另一个凭证。

凭证文件必须能被当前运行用户读取，按 UTF-8 保存。若调整了 `token_file` 文件名，也需要为新文件增加相应的 Git 忽略规则。

`GATE_API_TOKEN` 是业务后端的访问凭证，与接收程序内部随机生成的令牌、MySQL 密码、业务后端的 `GATE_DB_PASSWORD` 都不同。

## 3. 第一次运行升级版本

1. 在原接收窗口按 Ctrl+C 停止旧进程，避免两个版本同时访问数据库或占用端口。
2. 双击 `check_config.cmd`。应显示停车场 LOT-DEFAULT、凭证已加载、同接口最小间隔 3 秒。
3. 双击 `start_backend_receiver.cmd`，输入本机 MySQL 密码。
4. 首次正常启动会升级本地后端记录及审计表；检查日志有无迁移错误。
5. 在接收电脑打开 `http://127.0.0.1:18081/health`。
6. 用一次新的正常识别进行入口测试，再以同一车牌测试出口。

配置检查仅加载配置及凭证，不建立数据库连接、不执行迁移、不请求业务后端。
正常启动才执行本地 SQLite 迁移。此次开发测试全部使用临时库，没有预先迁移你的现场业务记录。

### 数据怎样保留

`backend_events.sqlite3` 的旧 `backend_events` 表保留为 `backend_events_v02`，新表复制全部旧行，并增加停车场、HTTP 状态和 Retry-After 字段。
新主键是“后端地址＋停车场＋相机 ID＋识别秒＋规范化车牌＋方向”。原来的 allowed、pending、uncertain、denied 等状态不变，历史事件不会因此重新提交。

迁移在同一个事务内完成，失败即回滚。重复启动不会重复迁移。遇到异常不要删除旧表或去重数据库绕过错误。

`receiver_audit.sqlite3` 只新增事件的 `backend_url` 和 `lot_id` 字段。旧审计没有这些信息，因此保持空值，历史详情会显示 `backend_context_unknown=true`，不按当前配置猜测所属订单。
后端旧订单仍可通过保留的后端记录和实际后台核对。

接收程序本机 MySQL 的采集表没有因本次升级改变。文档提到的 `gate_park_record` SQL 迁移属于业务后端服务器，不在本项目中执行。

## 4. 限流与超时的实际行为

后端按“同一来源 IP＋同一路径”限流，不能按车牌或相机分别计算来绕过限制。
本程序在单个接收进程内为同一后端同一路径共享发送锁，入口和出口分别使用自己的锁。
不同停车场、不同相机通过该进程请求同一路径也会等待。

本地等待使用请求的剩余预算，默认整个内部处理预算仍是 6 秒：

```text
新识别事件 → 保存记录并取得本地去重资格
           → 等待本接口时隙（仅在剩余预算内）
           → 带凭证请求后端
           → 检查车牌、停车场、lift
           → 未过期才返回开闸和语音
```

如果冷却时间已经超过剩余预算，记录 `not_sent`，本次不请求后端、不发送开闸或语音。
后台没有一个脱离当前 HTTP 请求继续排队的开闸任务。

HTTP 429 返回有效整数 `Retry-After` 时，会把它作为后续新事件的冷却下限；无效或缺失时仍保留配置的最小间隔。
冷却时刻保存在 SQLite 中，进程重启也会读取。程序不会假造 `X-Forwarded-For` 来规避后端限流。

本实现按“上一次请求结束后再等 3 秒”计时，比按请求开始时刻计时更保守，因此不会达到每秒多车的吞吐量。
正式现场如果车辆通行频率更高，应与后端一起调整限流策略。请保持一个接收进程运行；多个独立进程/电脑或其他客户端共享出口 IP 时，需要统一规划。

已有去重策略仍然保留：401、429、not_sent 等事件也不会因为相机重复发送就自动再次请求后端。
修正凭证或网络后，应核对停车单与现场状态，再进行正常的新识别测试，不要批量重放旧出口请求。

## 5. 如何判断是否正常

`/health` 新增以下信息：

```json
{
  "backend_lot_id": "LOT-DEFAULT",
  "backend_auth_configured": true,
  "backend_min_interval_seconds": 3.0
}
```

这里只展示字段示意，实际响应还包含其他状态。`backend_auth_configured=true` 仅表示加载了凭证，不表示远端已验证通过。

| 日志/状态 | 含义及处理 |
| --- | --- |
| `auth_failed` / HTTP 401 | 检查文件里的凭证是否与后端实际配置相同，环境变量是否覆盖了文件 |
| `rate_limited` / HTTP 429 | 查看 Retry-After、其他同 IP 客户端；本次不开闸、不播报 |
| `not_sent` | 本次预算内没有发送机会；结合审计和现场核对 |
| `rejected` | HTTP 正常但业务 `code=500`，查看返回原因 |
| `uncertain` | 连接/超时/格式/车牌或停车场不匹配等；不能确认本次可放行 |
| `allowed` | 后端允许；还需看发送状态及现场结果 |
| `IO1=True voice=True response=written` | 开闸与播报回复已写入连接，不是机械/喇叭执行回执 |

`/events/{request_id}` 中关联的后端记录会显示 `lot_id`、`http_status`、`retry_after`。
响应 JSON 仍保留计费字段用于核对；可能回显当前访问凭证的字符串会被替换为 `[REDACTED]`。

仍然仅根据 `lift` 决定开闸：演示模式可同时 `needPay=true`、`lift=true`。如果开启支付后返回 `lift=false`，本程序不放行。
支付成功后的主动通知/再开闸流程不在当前文档提供的接口范围内，本次没有自行添加支付轮询。

## 6. 网络和时间检查

v0.7 文档写明服务器 profile 可以只监听 `127.0.0.1:83`。如果实际如此，另一台电脑直接访问服务器局域网 IP 的 83 端口无法成功。
需要把 `url` 配成部署方实际提供的代理根地址，或由部署方调整服务监听。本次保留你原来的地址，没有猜测代理端口或修改远端服务器。

识别时间继续使用相机原始秒时间戳乘 1000，形成毫秒值。新版会拒绝早于规定日期或比后端当前时间快 10 分钟以上的时间，应校准相机时间。
返回的 UTC 时间文本与北京时间相差 8 小时；Unix 毫秒时间戳本身不要再加 8 小时。
