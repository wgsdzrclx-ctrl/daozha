# 出口收费金额语音说明

更新日期：2026-11-09。

## 1. 现在会播报什么

在 `[voice] enabled=true`、出口后端返回 `lift=true`、金额有效且响应没有超时的情况下：

```text
入口：车牌号 + 原来的入口提示语
出口：车牌号 + 金额 + 收费金额 + 元 + 原来的出口提示语
```

例如 `billingAmount=12.50`，预期听到“粤 B 一二三四五，金额十二点五零元”；
若 `exit_suffix=goodbye`，末尾还有“一路平安”。

这里按你的要求把 `billingAmount` 当作此次收费金额，单位为元；接收程序不重新计算费用。
但你提供的普通语音目录没有“本次收费”词条，已确认 `0x22` 支持的词条是 `0x2D`“金额”。
因此当前用“金额”表达收费信息，不能声称设备会完整说出“本次收费”。
要实现准确措辞，需要厂家提供这句话的语音词条及编码，或验证支持自定义词条/任意文字的设备。
`0xFD` 在你此前的测试中没有反应，本次继续使用已成功的 `0x22`。

开闸和语音在同一次 HTTP 回复中下发，并不等待闸杆抬起到位。

## 2. 数据流及代码位置

```text
出口识别车牌
  → camera_service.py 保存事件并调用 backend.decide()
  → gate_backend.py 请求一次 /gate/exit，保存原始后端响应
  → camera_service.py 通过 backend.lookup() 读取已保存的 response_json
  → 只有允许放行的出口提取 data.billingAmount
  → done(..., billing_amount=amount)
  → camera_voice.build_open_reply(..., billing_amount=amount)
  → build_voice_frame() 组合车牌、金额和提示语
  → validate_camera_reply() 校验命令、长度、CRC、金额语法和 GPIO
  → 相机通过 RS485 把 0x22 指令交给控制卡
```

`lookup()` 读取本地后端调用记录，不再次调用 exit 接口。重复事件也不会为了语音重新请求后端。

### camera_service.py：提取及降级

允许放行后，以 `json.loads(..., parse_float=Decimal)` 解析 `record['response_json']`，
读取 `response['data'].get('billingAmount')`。只处理出口且语音启用的事件。

正常金额交给 `done()`，日志追加 `voice_amount=12.50`。
金额缺失、null、负数、布尔值、非法文本、非有限数或超出支持范围时，
日志追加 `voice_amount=skipped`，退回车牌和原提示语，不把异常当成免费，也不改变后端放行决定。

### camera_voice.py：金额编码

- `normalize_billing_amount()`：用 `Decimal` 校验并按 `ROUND_HALF_UP` 四舍五入到两位小数。
- `_integer_voice()`：生成带十、百、千、万的读法。12 编成“十2”，避免读成“一二元”。
- `amount_voice_bytes()`：拼接 `0x2D`、整数读法、“点”、两位小数、“元”。
- `build_voice_frame()`：在车牌之后、原提示语之前插入金额；重新计算长度与 CRC。
- `build_open_reply()`：只在 `direction='out'` 时使用金额；入口即使传入金额也忽略它。
- `_validate_amount_voice()`：反解金额并重新编码比对，拒绝夹带额外词条、非规范数字等内容。
- `validate_camera_reply()`：保留单条 `0x22`、固定 `io1/on`、CRC 及规范 JSON 的原有约束。

以 12.50 元为例，金额段是：

```text
2D CA AE 32 B5 E3 35 30 D4 AA
│  │     │  │     │  │  └─ 元（GBK）
│  │     │  │     └──┴──── 小数 50（ASCII，逐位读）
│  │     │  └───────────── 点（GBK）
│  │     └──────────────── 2（ASCII）
│  └───────────────────── 十（GBK）
└──────────────────────── 金额（语音目录词条，不是 ASCII 文本）
```

`0x22` 是外层命令号；`0x2D` 是载荷中的“金额”词条，两者含义不同。
不能把整句“本次收费12.50元”直接 GBK 编码后发给普通语音卡。

金额播报范围是 `0` 至 `99999999.99` 元，因为当前目录只确认到“万”，没有“亿”。
范围外的值不会截断或改报零元，而是退回原车牌播报。

| 后端值 | 金额部分预期读法 |
| --- | --- |
| 0 | 金额零点零零元 |
| 5 | 金额五点零零元 |
| 12.5 | 金额十二点五零元 |
| 101.01 | 金额一百零一点零一元 |
| 1.005 | 金额一点零一元（四舍五入） |
| 缺失、null、负数、非法值 | 不播报金额，保留车牌及原提示语 |

## 3. 如何测试

1. 停止旧接收程序，运行 `check_config.cmd`，确认语音启用。
2. 运行 `start_backend_receiver.cmd`。本次不需要新增 INI 字段，也不需要改相机上报地址。
3. 正常识别一次入口，确认入口仍按原来的方式播报。
4. 识别一次新的出口事件；后端需返回与本次车牌、停车场匹配的数据、`lift=true`，以及有效 `billingAmount`。
5. 查看日志中的 `voice_amount=...`、`voice=prepared` 和实际响应写入日志，现场听是否正确。
6. 分别验证零元、整数及小数；检查未放行时没有语音。

`voice_amount=12.50` 表示金额已取出并准备编码，不是设备播放回执。
`response=written` 也不能证明喇叭播放完成；最终以设备实测为准。
相同事件会被去重；反复拿同一事件测试不会反复播报，需使用正常的新识别事件。

如果只有车牌声音，先查 `voice_amount=skipped` 和后端原始响应的 `data.billingAmount`。
如果有“金额”但数字不完整，请提供实际播报内容和日志，进一步核对控制卡固件的词条支持。

## 4. 测试覆盖及边界

自动化测试只使用临时数据库和本机模拟后端，不请求真实计费服务器或真实相机。
覆盖零元、整数、小数、四舍五入、金额缺失/异常、入口保持原样、后端拒绝、事件去重、
带金额回复超时撤回、CRC/长度及正确 CRC 下非法语音内容的拦截。

本次仍只在允许开闸时播报。没有添加 `lift=false` 时催缴费用，也没有查询支付或延迟补发逻辑。
